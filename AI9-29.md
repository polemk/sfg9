## 🔴 1. ALTO — IDOR no chatbot do blog (vaza histórico de leads)

**Arquivo:** `backend/app/services/blog_chat_service.rb` → `find_or_create_lead`.

**Problema:** usa `Lead.by_any_id(session_id)` com o `session_id` vindo direto do cliente
(localStorage). Como casa com "qualquer id" de Lead, um visitante pode passar o id/UUID de
outro lead — inclusive um contato real do CRM — e o `build_history` monta a conversa a
partir de `lead.messages`. Permite ler conversas de terceiros enumerando ids.

**Correção:** restringir o lookup ao próprio fluxo de blog (ex.:
`Lead.where(source_type: 'chat').where("source_id LIKE 'blog_%'")`) e casar **somente** por
`session_uuid` exato. Nunca resolver por id numérico do CRM. Adicionar teste cobrindo o
caso de session_id de outro lead → não deve retornar histórico alheio.

## 🟠 2. MÉDIO — Endpoints públicos sem rate limit / anti-abuso

**Arquivo:** `backend/app/controllers/api/v1/public/posts.rb` → `POST .../chat` e
`POST .../comments`.

**Problema:** abertos, sem auth, sem rate limit. O `chat` chama o provider de IA a cada
request (custo de LLM = qualquer um pode queimar créditos). O `comments` aceita comentário
anônimo sem moderação (spam publicado na hora).

**Correção:** adicionar `rack-attack` com throttle por IP (ex.: chat 10/min,
comments 5/min); honeypot ou moderação/aprovação nos comentários. Considerar um teto
diário de chamadas de IA no chat por sessão/IP.

## 🟠 3. MÉDIO — Vazamento de e-mail dos comentaristas (LGPD)

**Arquivo:** `backend/app/controllers/api/entities/comment.rb`.

**Problema:** a entity expõe `author_email` e é usada no endpoint público
`GET .../comments` → e-mail de todo comentarista fica exposto na API pública (colheita de
e-mails / dado pessoal).

**Correção:** remover `author_email` da entity pública. Se precisar do e-mail no admin,
criar uma entity separada (ex.: `CommentAdmin`) usada só nas rotas autenticadas.

## 🟡 4. BAIXO/VERIFICAR — XSS armazenado em comentário

**Arquivo:** componente de comentários no frontend (verificar `frontend/src/...`).

**Problema:** `Comment#body` vem de input anônimo e é exposto cru. Se o front renderizar
com `dangerouslySetInnerHTML`, é XSS estável; se renderizar como texto (React escapa),
está ok.

**Correção:** confirmar que o body do comentário é renderizado como texto. Se houver HTML,
sanitizar (DOMPurify) ou escapar. Adicionar sanitização no backend ao salvar como camada
extra.

## 🟡 5. BAIXO — `rescue_from :all` devolve backtrace ao cliente

**Arquivo:** `backend/app/controllers/api/root.rb` (pré-existente, fora da stack de posts,
mas tratar junto).

**Problema:** no 500, `error!(error_backtrace, 500)` devolve o stack trace completo
(caminhos de arquivo, internals) ao cliente.

**Correção:** responder mensagem genérica ("Erro interno") ao cliente e manter o backtrace
só no `Rails.logger`. Confirmar também que o header `X-Skip-Auth: 1` é removido pelo proxy
de borda em requests externos.
