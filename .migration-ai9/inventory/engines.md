> Escopo: as 7 engines locais montadas pelo SFG (`engines/`, declaradas em `Gemfile.linux:6-12`),
> inventariadas **como capacidades de plataforma**. O comportamento de auth do ponto de vista do app
> (login, sessão, impersonation, permissões efetivas) está na faixa **001–049** — aqui os pontos de
> sobreposição apontam "ver também faixa 001–049" em vez de duplicar a regra.
> O retrato completo do banco é da faixa **540–599** — aqui as tabelas são apenas listadas e apontadas.
> Todos os caminhos são relativos a `\\wsl.localhost\ubuntu-22.04\home\vinao\workspace\sfg`.

**Notas transversais (valem para todas as engines):**

- Todas usam o mesmo esqueleto: `isolate_namespace`, `paths["app/views"] << "app/views/livetat/<engine>"`, initializer `:append_migrations` (copia `db/migrate` da engine para o app) e um `config.to_prepare` que carrega `app/decorators/**/*_decorator*.rb` da engine **engolindo exceções** (ver OPS-509).
- **Sprockets está desabilitado** no SFG: `config/application.rb:4-12` não requer `sprockets/railtie`, não existe `config/initializers/assets.rb`, e os layouts usam `javascript_packs_with_chunks_tag` (webpacker). Portanto **todo `app/assets/**` das engines é inerte** — exceto arquivos lidos direto do disco via `File.new` (avatar padrão do usuário, logos de e-mail).
- Os blocos `Deface::Override` ativos (`engines/auth_ux19/app/overrides/*.rb`) apontam para `layouts/livetat/materialize_wrapper19/**`, engine que **não existe** neste repositório → nenhum override deface tem efeito (`grep materialize_wrapper19` só encontra as próprias overrides e o partial `_exit_from_app_item.html.erb:2`).

### Modelo de navegação do console do SFG (o que o ai9 precisa reproduzir)

> Registrado aqui porque foi pedido junto com a navkit — mas **não é código de engine**.
> Fontes: `app/helpers/application_helper.rb:100-172` (dados), `app/views/pub/console/base/menu/_container.html.erb:1-43` (render), `app/frontend/js/simple_menu.js:1-60+` (estado ativo), `config/routes.rb:44` (rota).

- **Estrutura**: lista de *grupos*, cada um com `identifier`, `title`, `icon_class` (ícones zmdi), `default_topic`, `resource` e uma lista de `items` (`identifier`, `title`, `resource`, `topic`, opcionalmente `locked` e `target`). Grupo sem itens vira link direto (classe `independent_group_menu_item`); grupo com itens ganha o chevron `zmdi-chevron-down` e um submenu `inner_menu_items`.
- **Grupos e permissões** (`application_helper.rb:103-169`):
  - `dash` — "Início" (sempre visível, sem itens).
  - `results_group` — "Gestão": só se `current_user.projects.count > 0`. Itens: Controle de Risco, Painel de Disponibilidade (`locked`), Recebíveis, Renegociações, Indicadores, Operações de Risco, Operações Estruturadas.
  - `project_group` — "Projeto": o **grupo aparece sempre**, mas os itens só se `projects.count > 0`. Itens: Cobranças (`locked`), Disponibilidades (`locked`), Empresas, Fornecedores, Garantias, Indicadores específicos, Limites, Remunerações.
  - `management` — "Cadastro": só se `og? || admin? || manager?`. 17 itens: Projetos, Carteiras, Contas, Grupos de Portadores, Indicadores, Padrões de Disponibilidade (`locked`), **Permissões — só se `!current_user.may?("user_is_readonly")`**, Portadores, Segmentos, Subsegmentos, Tipos de Movimentação, Tipos de Recebíveis, Tipos de Recursos, Tipos de Limite, Tipos de OP Estruturada, Movimentações de Risco, Tipos de garantia.
  - `admin_settings` — "Admin": só se `og? || admin?`. Item: Central de ajuda.
  - `account` — "Perfil" → Minha conta. `faq` — "Ajuda" (sem itens).
- **Estado por item**: `locked` (herdado do grupo → classe CSS `locked` + `data-locked`) e `inactive` (hard-coded para o identifier `reports`, `_container.html.erb:24`).
- **Estado ativo**: `SimpleMenu` casa o `data-url` do item com a URL corrente e aplica a classe `selected` (`simple_menu.js:22-61`); a rota canônica é `/u/console(/:resource)(/:topic)(/:section)` (`config/routes.rb:44`).
